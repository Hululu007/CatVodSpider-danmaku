# 双站章节数据接入

数据来源为 [IntroDB](https://api.introdb.app/) 和 [TheIntroDB v4](https://theintrodb.org/docs)。两站读取均无需注册或 API Key。TMDB 继续用于识别作品、季和集；不下载整个数据库、不提交用户播放信息到贡献接口。

- IntroDB 使用 IMDb + 季集 `/segments`，读取片头、回顾、片尾和彩蛋。
- TheIntroDB 使用已经匹配的 TMDB ID + 季集 `/v4/media`，由服务器转换 TVDB 编号；带当前视频时长、`details=true` 和 `merge_unknown=false`，读取多段片头、回顾、片尾和预告。影片查询不带季集。
- 使用现有后台执行器；每站请求最多 8 秒，失败不影响播放。TheIntroDB 429 按返回等待时间延后请求。
- 2026-11-14 起按标记类型选择数据源：IntroDB 有有效片头、回顾、片尾或彩蛋时使用其数据；对应类型没有有效数据才用 TheIntroDB 补充。两站时间不同仍采用 IntroDB，不平均、不因备用站不同而取消主站自动片头。章节列表也仅显示被选中的数据，缺失类型可保留备用站多段标记。
- 自动片尾仍是每次播放一次。分段片尾后有预告或彩蛋时仅作为章节，不直接下一集；TheIntroDB 有界片尾只有接近视频结尾才可自动下一集。
- 多段开始、结束写入独立 providerChapters，保留自定义章节与原生章节。章节按时间排序并去重。
- 查询缓存增加版本和片长，旧缓存重新获取；成功完整结果保留 7 天，失败或一站失败仅保留 15 秒。章节数据仍按原媒体身份保存，片长差超过 5 秒时清自动供应商数据重查，不清用户自定义章节或 History。
- 后两集预取不沿用当前集片长；实际播放片长已知时单独确认版本。
- 保留下方文字连续两次缩小 10% 的设置（原大小 81%）；集数、集标题前从 5 个普通空格再加 10 个，合计 15 个。Logo 改用 470×140px 固定区域，裁去透明边后等比放入、左对齐并垂直居中，窄屏或标题可用宽度不足时限制宽度。
