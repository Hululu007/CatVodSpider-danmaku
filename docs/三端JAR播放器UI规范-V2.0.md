状态：原生首版已实现并生成试用 JAR；全界面1:1与三端最终验收尚未完成。详见[原生首版实施记录](./播放器UI-原生首版实施记录.md)。

1. 新 `custom` 模式的主栏顺序以本次十入口设计为准，替代旧方案在 custom 下的十四按钮排列。
2. 原方案中的主线程要求、原生状态保留、生命周期、互斥接管、恢复和发布校验继续适用。

6. 弹幕搜索与章节保留原 JAR 弹出样式；新 UI 不增加音量条或静音按钮。
7. 原 App 的 TV 遥控器、手机/平板触摸与焦点方式是最高兼容约束；视觉调整不能改变原输入语义。

## 2. 支持对象与已知差异

源码、编译和后续发布目录统一为：`D:\SI\影视jar\CatVodSpider-danmaku-main`。

| 目标 | 已采集版本 | 应用 ABI | 控制区结构 | 主要交互 |
|---|---|---|---|---|
| T1：OK影视电视版 | 5.1.6 / 516 | armeabi-v7a | `control(LinearLayout)` 内的 `actionLayout` | 遥控器 |
| T2：OK影视手机版 | 5.1.6 / 516 | arm64-v8a | `control(RelativeLayout) → bottom → action(HorizontalScrollView)` | 触摸，横竖屏 |

适配器判断顺序：宿主构建信息 → 实际 UI mode/窗口配置 → 已验证的容器与按钮结构。ABI 用于原生资产兼容，不作为电视/手机/平板布局的分类器。

r7补齐T3容器兼容：LinearLayoutCompat不是系统LinearLayout子类，不能只做instanceof LinearLayout判断。保留宿主容器、原LayoutParams对象及其子类类型，通过公开方法访问方向/重力。独立测试必须覆盖归档T3 APK中的真实容器类，并将独立测试与平板宿主升级后的实测结果分开记录。

首次实现按上述三份已知构建适配；未知构建或多义结构回到 legacy。不能声称兼容所有 OK影视/FongMi 分支。

## 3. 产品目标与范围

视觉语言：深色玻璃、清晰层次、克制的蓝色强调、统一线性图标。主栏精简，原有功能可达，状态可信。

实施范围分为两个层次：

| 层次 | 本规范要求 | 接入边界 |
|---|---|---|
| 主交付 | 十入口底部栏、六类新玻璃面板、原搜索/章节弹窗、标题联动 | 调整功能入口呈现，保留宿主播放、输入分发与焦点行为 |
| 整体协调 | 顶部标题/返回区、播放按钮、进度条的视觉协调 | 优先保留宿主实例与布局；需要搬移时单独完成三端验证 |

不将宿主整个 `control` 根节点替换为自制根节点，不重写播放器渲染层、MediaSession 或播放服务。顶部与进度区尚不能安全协调时，保留原生并在验收表标记“原生保留”，不能算整套视觉全部完成。

顶部保留宿主返回、标题、投屏、设置等实际入口；已有集标题浮层继续承担剧名/本集标题展示，避免再加一份重复信息。投屏或全屏能力不因设计稿出现图标就视为可用。

## 4. Android 原生视觉规范

本节新主题仅用于新主栏及六类新面板。原 JAR 的弹幕搜索和章节沿用自身颜色、尺寸、透明度、字体及焦点效果，不套用本节主题。

### 4.1 单位与设计变量

1920×1080 仅作为视觉参考画布。实现使用 dp/sp 和当前播放窗口尺寸；不把桌面 px 原样搬到 Android。

建议以 `ToolbarTheme` 保存设计变量，颜色使用 `0xAARRGGBB`：

| 变量 | 建议初值 | 用途 |
|---|---|---|
| GLASS_BG | `0x9E121826` | 主栏底色，约62%不透明 |
| PANEL_BG | `0xC21E2637` | 功能面板底色，约76%不透明 |
| PANEL_FALLBACK_BG | `0xF0182030` | 高对比/低性能回退，约94%不透明 |
| ACCENT | `0xFF2585FF` | 当前选项、焦点和进度强调 |
| ACCENT_HOVER | `0xFF4698FF` | 鼠标悬停或聚焦的细微提亮 |
| ACCENT_SOFT | `0x2E2585FF` | 低强度选中背景 |
| TEXT_PRIMARY | `0xFFFFFFFF` | 主文字 |
| TEXT_SECONDARY | `0xFFB8C1D1` | 次级信息 |
| TEXT_MUTED | `0xFF7F899B` | 非关键辅助信息，需核对实际对比度 |
| GLASS_BORDER | `0x26FFFFFF` | 面板细边 |
| TOP_HIGHLIGHT | `0x1AFFFFFF` | 很轻的顶部高光 |

圆角层级：按钮8–12dp、面板18–22dp、主栏20–24dp。所有数值是三端调试起点，验收后记录最终值。

普通文字以实际合成背景达到可读对比为准；亮色视频使文字难读时提高底色不透明度，而不是增加霓虹光晕。当前选择同时用勾选/文字说明表示，不能只靠蓝色区分。

### 4.2 玻璃实现与能力分级

基础实现使用程序化 `GradientDrawable/LayerDrawable/StateListDrawable`、细边、顶部高光和适量 elevation；动画用 View 属性动画，不能给整个面板设置统一 alpha 而连文字一起变淡。

必须区分透明叠色与真正背景模糊：

| 档位 | 实现 | 使用条件 |
|---|---|---|
| 基础玻璃 | 深色半透明底、多层细高光、柔和阴影，背景色透出 | 三端首发基线，T1 默认 |
| 真背景模糊增强 | 仅使用宿主/平台明确支持的窗口背景模糊方案 | 独立验证支持开关、窗口要求、视频层合成及性能后启用 |
| 高对比回退 | 提高底色不透明度、减少阴影和动画 | 低性能、明亮画面、系统关闭模糊或兼容失败 |

Android 12 的窗口背景模糊需要系统支持，可能被省电策略或设备配置关闭；也不保证同一窗口内的自定义 View 能得到所需背景效果。必须验证实际窗口和 SurfaceView/TextureView 组合。

`RenderEffect` 对 View 自身输出做模糊，不等于 CSS `backdrop-filter`。不能把文字图标一起模糊，更不能宣称设置它就完成视频背景模糊。T1 Android 7.1.2 没有这条 API 能力。

禁止在播放期间循环截取整屏/PixelCopy再高斯模糊，禁止为了玻璃效果替换宿主视频渲染类型。基础档验收写明“基础玻璃”，真模糊未实现就不标为完成。实时视频仍可通过透明底色提供颜色变化。

### 4.3 图标与状态

图标采用统一线性风格，圆端点，约1.5–2dp笔画。不直接引入 Lucide React；使用同风格的程序化 Drawable/Path，或在确认最终 JAR 资源加载链路后采用矢量资产。引用第三方图标时保存对应许可证。

当前打包以 DEX 和指定 assets 为主，不假设新增 Android XML 资源会自动进入 JAR。首选程序化 UI 和图标，避免引用插件 APK 的 `R.drawable` 后在宿主失效。

| 状态 | 行为与视觉 |
|---|---|
| 默认 | 白色/浅灰图标，透明按钮底 |
| 悬停 | 轻微提亮；仅有鼠标时适用 |
| 按下 | 触摸缩至0.96；TV焦点缩放与按下缩放合成，避免闪跳 |
| 选中 | 蓝色描边/柔和底色加勾选，与焦点不同 |
| 焦点 | 清晰约2dp蓝色轮廓；TV可放大到1.04，预留不裁切空间 |
| 禁用 | 约45%–55%强度，不响应操作，同时提供可理解原因 |
| 加载 | 保留操作位置，显示短等待状态；不先改成功勾选 |
| 失败 | 恢复真实状态，简短提示，允许再次操作 |

普通动效180–220ms，TV可缩短到120–180ms；尊重系统减少动画设置。只在状态变化时启动，不运行永久呼吸、光扫、模糊动画。

## 5. 十入口主栏与三端排版

### 5.1 新顺序

```text
上一集  下一集  选集 │ 播放设置  弹幕  字幕  音视频  1.00×  章节  画面比例
```

全部功能都在一个悬浮主栏中；上一集和下一集仍是两个按钮。主栏弹幕项显示真实开关状态，倍速项显示宿主真实速度。状态尚未读取时显示中性占位，不默认假定开启或1.00×。

T1 从原功能行接入 prev/next；T2/T3 的 prev/next 原先位于中央图标区。新入口接通、真机操作通过且能恢复后，才隐藏重复的中央入口；不能直接把那两个原生图标跨容器搬走。任一功能未接通时，原入口继续可达。

### 5.2 尺寸起点

| 参数 | T1 电视 | T2 手机全屏 | T3 平板全屏 |
|---|---|---|---|
| 主栏高度 | 76–88dp | 64–72dp | 72–84dp |
| 单元目标宽度 | 76–88dp | 56–64dp | 72–88dp |
| 图标 | 24dp | 22dp | 24dp |
| 标签 | 16sp起，按观看距离验收 | 12–14sp | 14–16sp |
| 单元水平间隔 | 4dp | 4dp | 4dp |
| 主栏内边距 | 水平20dp | 水平12dp | 水平20dp |
| 外侧安全边距 | 至少24dp并留焦点放大区 | 至少12dp+系统栏insets | 至少24dp+insets |

触摸目标不低于48×48dp。不要为了十项一屏显示把触摸目标或文字压缩到难用。

用 `所需宽度 = 2×内边距 + 各单元宽度之和 + 间距 + 分隔线占宽` 与当前播放窗口比较：够宽时单行居中；不够时单行横向滚动，焦点/当前操作自动滚入可见区域。保持顺序、禁止换行和硬裁按钮；分隔线不可聚焦。

T2/T3 详情页原 action 默认隐藏，首发沿用该规则。十入口主栏默认只在宿主允许显示 action 的模式中出现；不把平板800×450px预览区塞成全屏控制台。若以后要求详情页也显示，作为独立布局能力验证。

### 5.3 顶部和进度区域

顶部使用轻量渐变遮罩协调原生返回、标题、投屏和设置，避免大块卡片重复。保留已有两行集标题的展示逻辑；移动主栏后重新计算标题与 control 的间距。

不添加音量条和静音按钮；保留原App音量键/手势。播放/暂停、当前位置、进度、总时长和全屏继续优先复用宿主。进度填充可采用蓝色、拖动圆点采用白色；拖动时间提示只显示真实位置。预览缩略图只有宿主提供时才显示，不能把静态图伪装成帧预览。

seek范围未知、直播不可拖动或 duration<=0 时按能力禁用拖动。正在拖动时保存预览位置，释放后提交seek，再读取实际位置；不要在每个像素移动时向宿主刷seek。

## 6. 功能归属：原按钮不能因收纳而丢失

| 原功能 | custom中的入口 | 数据/动作来源与要求 |
|---|---|---|
| 上集/下集 | 主栏独立按钮 | 原生prev/next或已验证导航桥；保留顺序/倒序语义 |
| 选集 | 选集面板 | 宿主当前线路的真实集列表和稳定ID |
| 内核、硬解/软解、画面比例 | 播放设置 | 实际能力与当前值；三者独立分区 |
| 刷新、重播、循环 | 播放设置底部“播放操作” | reset、可用的replay、T1/T2 loop或T3 repeat |
| 条件解析 | 播放设置“解析”区域 | T2可能为底部列表，T3是parse按钮，不能仅用名称归一化 |
| 弹幕搜索 | 弹幕面板内“弹幕搜索”入口 | 直接调用原 `showSearchDialog`，保留 Aurora 弹窗及搜索/推送链路 |
| 弹幕显示总开关 | 主栏状态+弹幕面板 | 宿主真实显示状态，不与自动推送开关混为一谈 |
| 弹幕设置 | 弹幕面板 | 复用现有已验证入口，逐步统一外观 |
| 字幕 | 字幕面板 | 真实轨道/外挂字幕；保留已有加载、同步等功能入口 |
| 音轨、视轨 | 同一音视频面板内两个Tab | 真实列表、语言/分辨率；缺字段不编造 |
| 倍速 | 独立倍速面板 | 实际支持范围和读取结果 |
| 原生片头、片尾手动标记 | 保留原生按钮及其已有菜单入口 | 原生短按/长按和清除行为保持；不在原章节侧栏新增编辑Tab |
| Auto识别跳过 | 原章节侧栏首行“Auto 去片头尾：开/关” | 原切换与ChapterManager/AutoSkipService逻辑 |
| 原生章节、插件章节 | 主栏“章节”调用原 `showChapterDialog` | 保留加载、RecyclerView及ScrollView路径，T1/T2 title与T3 chapter按原语义保留 |
| 版本/片源附加入口 | 播放设置“片源与版本” | T3 edition等按真实语义/条件展示，不凭文案“标题”猜业务 |
| 未识别的原生功能 | 保留原生入口 | 完成映射前不移除整个原行；必要时该布局继续legacy |

十入口是目标导航。弹幕搜索与章节复用原样是正式产品要求，验收记为“按要求原样复用”；其他尚未统一的宿主选择菜单单独记录兼容范围。

## 7. 新玻璃面板与原 JAR 弹窗

### 7.1 面板系统

建议由单一 `PanelHost` 管理当前面板：`NONE/EPISODES/PLAYBACK/DANMAKU/SUBTITLE/TRACKS/SPEED/ORIGINAL_SEARCH/ORIGINAL_CHAPTERS`。每个面板有 loading、ready、empty、error 状态，并保存来源按钮的 actionKey。

六类新面板视觉：18–22dp圆角，16–20dp内边距；标题行至少48dp以容纳关闭按钮；正文可滚动。T1优先从按钮上方弹出，触摸大屏可锚定或侧栏，窄屏采用安全的侧栏/底部面板；不硬套网页360px宽。

| 环境 | 面板起始宽度 | 边界规则 |
|---|---|---|
| T1 | 普通面板320–400dp；章节侧栏沿用约34%可用宽度 | 内容多时滚动，焦点不越界 |
| T2 | 普通面板约320dp并限制在可用宽度内；章节沿用约40% | 章节沿用原侧栏最小160dp及触摸行为 |
| T3 | 普通面板360–480dp；章节沿用约50% | 大屏可使用侧栏，保持触摸间距 |

原章节侧栏维持右侧全高、外部透明且不压暗视频，宽度基线TV34%/手机40%/平板50%及原最小160dp；具体分档沿用原JAR判断。不得改成统一圆角浮窗或三Tab。原弹幕搜索沿用配置lpWidth/lpHeight/lpAlpha（默认0.90/0.85/0.90）、Aurora青绿渐变、胶囊输入、来源标签、分组网格。两类原窗口可以依其原行为覆盖控制区，不强加新面板的避让布局。

新玻璃面板定位使用当前窗口可用区域与WindowInsets，先尝试锚点上方，不够时移到侧边或安全区域；不得使用上一次横竖屏的坐标。输入法出现时重新限制面板和列表高度，让搜索框、提交键和关闭键可达。小屏优先保证输入，无法同时露出进度条时临时收起主栏，结束输入后恢复，不强行堆叠。

一次只显示一个功能面板：切换面板先退出旧面板；开启宿主原生Dialog前关闭自有面板并进入“原生面板处理中”。只有可靠的关闭事件或窗口状态校验才能解除，不用固定延迟假定宿主面板已经关闭。

不要覆盖原生View已有的click/longClick/focus监听来偷取事件。无法可靠接管原生弹窗生命周期的宿主先使用兼容路径，不强行做自动隐藏和焦点承诺。

### 7.2 各面板内容

**选集**：真实总集数、当前集高亮、网格滚动、定位当前集、选中后等待宿主切集确认。有历史数据才显示已播放状态；不能默认前几集都已播放。无列表接口时保留原生选集入口，不生成假集数。

**播放设置**：内核、解码、比例、播放操作、条件解析、片源版本。原文“LJK”应改为“IJK”；候选不是硬编码EXO/IJK/系统，T3已有MPV证据。仅展示当前宿主确实支持的组合，内核不支持切软解时禁用该组合并解释。

**弹幕**：新面板仅提供真实总开关、显示控制、设置与“弹幕搜索”入口。点击搜索先关闭新面板，再调用 `DanmakuUIHelper.showSearchDialog(activity, currentEpisodeInfo)`；输入、来源、排序、分组、结果选择和设置按钮全部保留原样。搜索和自动推送设置不与渲染总开关混用。

**字幕**：关闭、真实内嵌/外挂轨道、当前选中勾选、长列表滚动。语言名只有元数据存在才显示；不存在的简中/繁中/英文不能作为可点假选项。保留字幕加载、偏移等原功能的可达路径。

**音视频**：一个面板内的“音轨｜视轨”Tab。切Tab不关闭面板；两个列表分别保存滚动和焦点。语言、声道、分辨率取真实元数据。某一侧不可用时显示原因或空态，不伪造默认轨道。

**倍速**：首选3列网格，候选0.5/0.75/1/1.25/1.5/2/3倍与宿主能力取交集。宿主当前值不在预置中时仍显示其真实值。提交后等待确认再更新主栏；被宿主钳制时显示实际值。

**章节**：直接调用 `DanmakuUIHelper.showChapterDialog(activity, anchor)`，保持原右侧列表；首行Auto切换，后续为前情回顾、片头开始/结束、片尾及章节。沿用加载侧栏→读取当前媒体→正式列表流程及失败文案，不展示上一集数据。保留原宿主 `dialog_episode_list` 的RecyclerView路径及现有ScrollView后备样式；不添加三Tab、时间输入或自制玻璃外壳。

## 8. 片头片尾与章节数据边界

原文的“片头/片尾起止区间”不能直接当成当前宿主已有能力：

- 插件片头段可有 `introStartMs..introEndMs`；原生opening通常只存一个结束位置，不能声称原生保存了两个端点。
- 插件片尾当前使用 `outroStartMs`；UI的片尾结束可显示“视频结束”或已知总时长，默认只读。用户可编辑任意outroEnd属于新业务能力，需要独立设计和验证。
- FongMi 5.1.6 已知History.ending表示距离结尾的剩余时长，按duration转换；不能直接写绝对outroStartMs。T3 5.5.6 必须验证自己的契约，不能仅因名称相同照搬。
- Auto结果保存到插件ChapterData，不写原生History.opening/ending，不改原生按钮文案。用户原生手动设置优先，不能被自动结果覆盖。
- 模式/样式回退不清除用户手动标记，不恢复成安装UI时的旧业务数据。
- 保留已有冷开场保护、手动拉回保护、seek冷却、当前集签名校验和章节持久化规则。
- 原生与插件章节合并时标明来源并按稳定ID/时间去重；不能用标题字符串唯一判断同一章节。

输入时间以明确格式显示，内部统一毫秒；校验非负、起止顺序和已知duration上限。时长未知时禁用依赖时长的换算，不写0凑数。

如设计需要分别关闭片头和片尾，先确认现有模型是否有分项开关；没有时保留现有总Auto开关，或另做数据迁移和行为测试，不能添加两个只改视觉的开关。

## 9. 播放器适配与可信状态

### 9.1 建议接口职责（新设计，非已实现API）

使用Java 8，接口可以按实际代码合并，至少覆盖以下语义：

| 方法类别 | 建议能力 |
|---|---|
| 发现与观察 | `capabilities()`、`readState()`、状态变化订阅/有限兜底同步 |
| 播放 | `play/pause/seekToMs` |
| 声音 | 无新增音量条/静音入口；实体音量键、宿主音量手势和系统提示保持原样 |
| 参数 | `setPlaybackRate/selectEngine/selectDecoder/selectScale` |
| 列表 | 读取及选择episodes/subtitles/audioTracks/videoTracks |
| 原生操作 | `refresh/replay/setRepeat`及条件parse/edition入口 |
| 标记与章节 | 通过已有ChapterManager和经验证宿主桥处理 |
| 窗口 | 请求进入/退出全屏、当前control显示状态、面板交互保持能力 |

`capabilities` 至少区分：可以直接执行、只能打开原生菜单、当前不支持、尚未验证。存在hasClick不等于存在可以选择具体内核/轨道的API。

动作结果不是单个“成功”布尔值，应能区分 `CONFIRMED/PENDING/UNSUPPORTED/FAILED`；通过回调或状态订阅确认宿主最终值。前端选择只进入pending，超时后显示未确认/失败并重读，不能一直保留假高亮。

时间seek、倍速、循环等不同动作设置适合的确认条件；切内核/换集可能重建页面，不能一律用500ms检查一次就判失败。每个请求关联当前媒体ID和会话generation，丢弃过期回调。

### 9.2 调用优先级

1. 复用现有已验证的插件能力、宿主公开入口或桥接。
2. 复用原生按钮实例及监听器，尽量保持原父级约束。
3. 对已验证的clickNode主线程调用performClick/performLongClick，仅用于相应原生动作。
4. 确有需要才加版本专用反射；不把私有Android监听器字段作为基础接口。

`performClick()` 能打开宿主内核选择，不代表能直接选择MPV/EXO，也不能保证隐藏按钮仍能作为弹窗锚点。`GONE + performClick()` 必须按按钮实测，失败就保留原生菜单/原位实例。

手动上一集/下一集复用宿主导航语义，特别注意倒序播放。不把供Auto片尾使用的 `nextEpisode()` 直接当所有“下一集”按钮的通用实现，以免绕开现有保护或日志语义。

生产界面不展示React/Web演示，不嵌WebView替代原生控制栏，不注入虚假的轨道、内核或播放结果。视觉开发用的假数据只出现在显式开发预览中，不进入默认播放流程。

## 10. 显隐与输入路由

### 10.1 显隐

当前三端由control祖先显隐，custom必须尊重宿主状态，不建立另一个每秒强行setVisibility的循环。

产品目标：操作时唤出，面板打开/输入/拖动/TV焦点操作期间保持显示，暂停时保持可操作，播放空闲时按宿主策略隐藏。原文3秒是设计参考；初版沿用宿主超时，修改必须通过适配器明确接管且三端通过，不能同时保留两个计时器竞争。

建议保持原因：`PANEL_OPEN/IME_OPEN/SEEK_DRAG/ACTIVE_INPUT/PAUSED`。每个原因有明确进入退出事件；释放最后一个原因后恢复宿主策略。仅能把浮层留在屏幕上却无法保持控制栏时，不能宣称该目标已完成。

功能栏隐藏不能吞掉正输入的面板；但切集、退出或宿主播放Activity失效必须关闭旧会话面板。旧面板不能悬浮到新的页面。

### 10.2 TV与触摸（实施硬约束）

先记录同版本原App操作基线，再逐项对照新UI。保留Activity/Window的按键和触摸分发，不安装覆盖宿主的全局OnKey/OnTouch拦截器；复用原点击/长按监听、ID、tag、焦点属性与宿主容器。不能仅让按钮可点击就认定兼容。新入口只处理自身动作，未消费事件交还宿主。

| 场景 | 路由 |
|---|---|
| TV主栏获得焦点 | 沿原App焦点方式左右导航、上下到原进度/控制区、确认/长按；只为新节点补必要连接，不重写整条焦点链 |
| TV面板打开 | 原搜索/章节保留自身导航与返回；新面板使用原生焦点搜索，关闭后恢复来源且不抢已有有效焦点 |
| TV编辑框/输入法 | 保留正常输入；返回先由IME处理，再处理面板 |
| 控制栏隐藏的视频区 | 未由新UI消费的键交还宿主，保持原快进/音量行为 |
| 手机/平板 | 保留原点击、滑动/拖动、长按、双击、系统返回、旋转及全屏语义；沿用原触摸焦点属性，不套TV强制焦点策略 |

不能把原文“左右永远seek5秒、上下永远调音量”全局套到电视，会破坏导航。额外键盘Space/F/M/[]/N/P只在宿主支持、不冲突、非输入框、无面板操作时选择性接入；初版默认不增加全局拦截。

原章节的focusableInTouchMode和首行补焦点属于已有行为，应原样保留；新触摸面板不额外强抢焦点。HTML键盘导航只是预览辅助，不是Android实现规格。原操作失效、重复触发、焦点丢失/死循环、手势被抢、返回次序改变均为阻断验收问题。

新节点有contentDescription、可达焦点、选中说明。保留原生监听和tag，使用独立状态观察；焦点回来时若用户已经移到其他有效位置，不再抢回。

## 11. 工程结构、生命周期与恢复

建议文件都放入现有 `app/src/main/java/com/github/catvod/spider/` 可打包范围；以下为职责建议，不要求机械拆成大量空类：

```text
PlayerToolbarController.java  模式路由、单一接管、会话与恢复
PlayerToolbarAdapter.java     能力、状态、动作契约
ToolbarHostAdapters.java      T1/T2/T3结构与行为适配，可按规模拆分
ToolbarSession.java           Activity/媒体/generation、快照、监听清理
ToolbarTheme.java             颜色、尺寸、图标和状态样式
ToolbarPanelHost.java         单面板管理、定位、焦点与显隐保持
DanmakuUIHelper.java          复用现有弹幕/章节UI及面板构建入口
PlayerToolbarProbe.java       有限诊断，默认关闭
```

状态统一由控制器/会话管理，不由每个按钮自行创建Timer。复用Init现有生命周期通知，不再注册一套重复Hook；保留跨ClassLoader的进程级重复实例防护。

`legacy/diagnose/custom` 互斥：新控制器成功绑定后，旧sync/arrange/弹幕搜索按钮注入/章节按钮注入都不能运行（原showSearchDialog/showChapterDialog继续复用）。识别失败先恢复原状态再启用legacy，本会话停止反复重试接管。

读写View和原生播放器控制在主线程；网络、解析和文件I/O在后台。异步工作校验当前Activity、媒体签名和generation。旧根节点失效时移除所有自行注册监听、Runnable与动画，不把旧View放到新Activity。

记录原父级、索引、LayoutParams类型、样式、焦点属性和修改记录。回退只恢复本UI修改，不恢复过期的倍速、比例、内核或手动标记。若宿主也更新了相同属性，按当前宿主状态恢复而非盲目快照覆盖。

恢复开关放在现有局域网配置页或另一个不依赖新主栏的入口。关闭custom后本地选择保持有效，不能马上被ext覆盖重新打开。未知宿主、异常重复、能力解析失败都应可回到legacy。

## 13. 性能、验证与交付

主线程稳定播放不做完整树遍历、重复安装、循环布局或实时全屏采样。状态读取优先事件，必要的轻量兜底仅在活跃会话；面板关闭后停止无关列表更新。

三端分别用同片源、同内核、同分辨率对比legacy/custom，记录开栏、切面板、滚动、弹幕流畅度、掉帧/主线程耗时和内存趋势。环境指标不齐时写清未量化，不凭肉眼承诺“零性能损耗”。T1默认基础玻璃，验证后才讨论增强。

项目无现成测试框架；编译是基线，真机验证覆盖操作语义。必要的纯逻辑测试优先用于模式互斥、能力过滤、状态确认、过期回调丢弃和History换算，避免只测试样式常量。

构建：`gradlew.bat assembleRelease --no-daemon`；需要上机时再运行 `jar\genJar.bat`。APK是中间产物，最终为dex JAR。新类和资产必须验证进入最终包，不能仅检查APK。

每次生成custom_spider.jar后，按原方案同步本地 `D:\SI\影视jar\index.js` 两处MD5并做语法检查；部署时校验本地包、实际下载包和/tv的MD5一致。danmu.jar仅在实际需要时单独生成；通常不为32/64位Java UI分别打包，但两种ABI的原生资产均需可用。

最终交付：修改源码清单、程序化样式/图标、三端宿主适配与能力清单、配置和恢复说明、最终JAR/MD5、三端验收结果及已知限制。所有报告区分“已实现且实测”“原生兼容保留”“不支持”“未验证”。不输出一个笼统的“全部功能已完成”。
