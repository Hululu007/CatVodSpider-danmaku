# 搜索结果进入详情页的加载卡顿

2026-11-08，TV 192.168.31.41:5555，p230 / Android 7.1.2，OK影视5.1.6/516。

## 原因与修复

- 主线程实采栈命中 `FongMiNativeHelper.currentHistories → collectObjectsByTypeName`。详情加载阶段 History 字段已存在但为 null，旧逻辑误走全对象图递归；旧 count 只计算匹配项，未约束访问数。现按类型缓存 Field，每次读取当前值；已知字段为空直接返回，兼容递归以 visited 数限制240对象。T1/T2/T3归档分别有 g0/b0/h0 History 字段，不依赖这些混淆字段名实现。
- TV实采栈多次命中 `CustomSeekView.a → B.a.run`。T1/T2 516归档证实空播放地址分支直接 post 自身，持续 setText/进度刷新；非空分支才使用200–1000ms延迟。
- 新 `HostLoadingGuard` 严格限定包名、516版本、CustomSeekView及C3.e/F3.f类型；加载为空时暂停原刷新门控，200ms轻量检查地址，恢复后交回原生刷新。各Activity独立管理；detach停止，reattach重新检查，destroy不重启空循环。T3不应用这条宿主特例。
- Init在播放Activity resumed/热加载检查中安装，destroy释放。原功能栏、时间轴输入及跳过规则未改。
