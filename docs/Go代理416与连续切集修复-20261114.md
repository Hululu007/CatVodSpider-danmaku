# Go 代理 416 与连续切集修复

设备 192.168.31.41 的日志显示，上游分片返回 416 后，本地代理返回空 HTTP 200。
IJK 在准备后约 0.1–0.22 秒报告播放完成，宿主随后自动下一集。用户反馈 EXO 同样失败。
这解释了此次连续切集行为；上游链接失效或权限错误仍须由片源提供方处理。

源码来自 https://github.com/Silent1566/GoProxyAndroid ，提交
aca8a796f436e8b92288316266327daacfa14de6。MIT 许可保留于 tools/go-proxy/LICENSE，
并嵌入二进制，通过 /license 返回。

用原版源码复现：bytes=1000-1010 被发成 bytes=1000-2010，返回 1011 字节而非 11；
上游 416 在原 main.go 的错误路径变成无内容 HTTP 200。

修复位于 tools/go-proxy：首块按长度正确计算、单字节请求、文件末尾裁剪、明确响应长度、
分片响应范围与长度校验、失败时从未输出字节续传。续传拒绝忽略 Range 的全文件 200，
已输出后的失败断开连接，防止将截断流标记为正常结束；尚未输出则返回明确错误。
保留多线程，永久 4xx 不重复重试。Authorization/If-Range 保持透传。

GoProxyBinaryCache 用资源 SHA256 生成独立可执行缓存文件；不覆盖旧运行映像。
GoProxyManager 检查 BUILD，只有当前版本才可复用，更新后无需手工删除缓存。
BUILD 为 go-range-20261114-r1。两份代理使用 Go 1.25.5、NDK r26b、Android API 24 编译。

本地验证：原版两项故障复现、新版 Go 11 组回归、go vet、Gradle assembleRelease/lintVital、
Java 16 项检查、JAR 四条目/ABI/DEX/许可证检查。Go race 未运行，主机未配置 C 编译器。
本地 index.js 两处 MD5 已同步并通过 node --check。

交付 jar/custom_spider.jar。用户替换服务器 JAR 时同步线上订阅 MD5，然后完全退出并重启影视。
本次未部署服务器、未修改电视配置、未推送 GitHub；实际带权限片源须在升级后复测。
详细哈希及验证边界见 build/danmaku-search-20261114/proxy-range-release/verification.json。

后续用户换包后的只读监控已确认 go-range-20261114-r1、IJK/EXO 首帧；同一集在约31秒窗口内进度持续递增，未记录416、播放完成或FATAL。证据为 build/danmaku-search-20261114/playback-after-upgrade-monitor.json。该记录不代表所有片源或后续UI包均完成上机验收。
